# Automated AWS Infrastructure & API Dashboard Provisioning

Infrastructure-as-Code project using AWS CLI, Bash, and Ansible to provision and harden EC2 servers, deploying a self-updating GitHub API rate-limit dashboard with Vault-encrypted secrets.

## 🏗️ Architecture & Workflow

1. **Infrastructure Provisioning (`deploy.sh`)**: Uses the AWS CLI to create an SSH Key Pair, a Security Group (allowing ports 22 and 80), and an Ubuntu 24.04 EC2 instance.
2. **Configuration Management (Ansible)**: Seamlessly takes over from the bash script to configure the host with true idempotency.
   * **Common Role**: Updates and upgrades system packages.
   * **Security Role**: Hardens the server by configuring UFW (Uncomplicated Firewall) with a default deny policy, disables root SSH login, and utilizes a handler to dynamically restart the SSH daemon only when configurations change.
   * **Dashboard Role**: Installs Nginx, `curl`, and `jq`, and deploys a cron-automated Bash script.
3. **Application Layer**: A templated Bash script uses `curl` to authenticate with the GitHub API, parses the JSON response with `jq`, and dynamically generates a static HTML dashboard served by Nginx.
4. **Secrets Management**: GitHub API credentials are securely injected at deployment time using Ansible Vault, ensuring they are never stored in plaintext within the repository.

## 📋 Prerequisites

Before running this project, ensure you have the following installed and configured on your local machine:
* **AWS CLI**: Installed and configured with `aws configure` (requires IAM permissions to create EC2 instances, Security Groups, and Key Pairs).
* **Ansible**: Installed locally.
* **jq**: Command-line JSON processor.
* **GitHub Personal Access Token**: Used only to check your own API rate limit, so no special scopes are required — even an unscoped/classic token works fine for this.

## 🚀 Setup & Deployment

### 1. Clone the Repository
```bash
git clone https://github.com/Ritvik-S-Rao/ansible-secure-server-provisioning.git
cd ansible-secure-server-provisioning
```

### 2. Configure Secrets (Ansible Vault)
This project uses Ansible Vault to securely inject GitHub API credentials into the EC2 instance without exposing them in plaintext. You must create an encrypted vault file before running the deployment.

Generate the encrypted vault file in the correct directory:
```bash
ansible-vault create inventories/dev/group_vars/all/vault.yml
```
You will be prompted to enter a new master password. Do not forget this password, as you will need it during deployment. Your default terminal text editor will open. Paste the following variables and replace them with your actual GitHub credentials:
```yaml
github_username: "YOUR_GITHUB_USERNAME"
github_token: "YOUR_GITHUB_PERSONAL_ACCESS_TOKEN"
```
Save and exit the editor. The file is now safely encrypted (and is safely ignored by Git via the `.gitignore` file).

### 3. Make Scripts Executable
Grant execution permissions to the deployment and teardown scripts:
```bash
chmod +x deploy.sh teardown.sh
```

### 4. Run the Deployment
Execute the master deployment script:
```bash
./deploy.sh
```
* The script will provision the AWS resources and wait 90 seconds for the server to boot.
* You will be prompted to enter your Ansible Vault password.
* Ansible will configure the server and deploy the application.
* Upon completion, the terminal will output the Public IP address of your new live dashboard.

### 5. View Your Dashboard
Open `http://<PUBLIC_IP>` in your browser — your live GitHub API rate-limit dashboard, auto-refreshing via a server-side cron job.

## 🧹 Cleanup & Teardown

To prevent incurring unwanted AWS charges, use the included teardown script to completely destroy the infrastructure. The deployment script automatically saves your instance and security group IDs to a local `.state.env` file for accurate teardown.

Execute the teardown:
```bash
./teardown.sh
```

## 📁 Directory Structure

```text
.
├── deploy.sh                  # Main infrastructure provisioning script
├── teardown.sh                # Infrastructure destruction script
├── playbook.yml               # Master Ansible playbook
├── .gitignore                 # Secures repo by ignoring keys, state, and vault
├── LICENSE                    # MIT License
├── inventories/
│   └── dev/
│       ├── hosts.ini          # Dynamically generated by deploy.sh
│       └── group_vars/all/
│           └── vault.yml      # Encrypted GitHub credentials (ignored by git)
└── roles/
    ├── common/
    │   └── tasks/
    │       └── main.yml       # OS update tasks
    ├── security/
    │   ├── tasks/
    │   │   └── main.yml       # UFW and SSH hardening tasks
    │   └── handlers/
    │       └── main.yml       # Restarts sshd only if config changes
    └── rate_limit_dashboard/
        ├── tasks/
        │   └── main.yml       # Nginx, cron, and app deployment tasks
        └── templates/
            ├── github-auth.sh.j2  # Helper script containing injected secrets
            └── rate-limit.sh.j2   # Main application logic and HTML generator
```
